# 聊天事件自動回覆

使用者需求：框選聊天區域；綠字是密語、白字是地圖聊天。新訊息交給 AI 依上下文決定回覆，送出後接續原腳本的下一個動作，保留迴圈與子腳本位置。

## 執行方式

每份腳本有選用的 `settings.chat_reply`。於播放器動作邊界輪詢；當前長按、拖曳或等待完成並放鍵後才處理聊天。沿用同一個 Player 的呼叫堆疊，不重新 `play()` 原腳本。此版不在長動作中途插入回覆。

設定以本次啟動的主腳本為準，監看涵蓋相同視窗的子腳本，子腳本自己的設定不在途中覆蓋主腳本。若只有子腳本啟用但主腳本沒有聊天服務，執行到該子腳本時明確中止並提示在主腳本啟用。子腳本切換到其他視窗時暫不觀察聊天。

首次擷取建立基準與上下文，不回覆啟動前的舊訊息。後續 OCR 逐行辨識並依字色分辨密語、地圖與其他內容；新綠字／白字觸發，其他內容僅供上下文。去除畫面重疊行與自己的訊息，保留最近 60 行以及已送出的回覆。

AI 沿用設定頁的供應商、模型與登入方式；收到框選區域截圖、上下文與待回覆訊息 ID。只允許輸出訊息 ID 與單行回覆文字。密語原則上回覆；地圖聊天先判斷是否與角色相關。回覆對象與頻道固定取自該 ID 的辨識結果，模型不能指定任意按鍵、程式或其他收件人。

## 操作設定

腳本編輯器增加「AI 自動回覆」設定入口：啟用、角色名稱、聊天框框選、提示詞、檢查間隔、AI 等待時間與回覆長度，以及地圖／密語兩份回覆操作。操作用既有動作編輯介面設定點擊、按鍵、組合鍵、延遲；另有「輸入回覆內容」「輸入對方名稱」按鈕。密語依使用者圖片的泡泡按鈕 → 對象對話框 → 聊天輸入框設定，實際座標由使用者取點。

兩份操作均需包含一次回覆內容；密語還需在回覆前包含一次對方名稱。使用者補充 `H` 可直接開啟密語對象對話框，因此預設密語流程以 H 開頭。每次送出之前重新確認並啟用原目標視窗。執行聊天操作時不執行原腳本輸入。

## 追加需求

- OpenRouter：API Key 與自行輸入模型名稱，共用聊天助手及自動回覆供應商工廠。
- Codex／Claude：依官方資料更新模型選單，允許填入新模型；Codex 可由 runtime 更新可用清單。
- 編輯器可在迴圈中新增、編輯第二層迴圈，回覆後保留兩層迴圈進度。

## 錯誤與停止

AI 失敗、逾時或無回覆：記錄原因並接續腳本；不盲目重試同一則訊息。AI 等待可由停止事件中斷，晚到結果不能送出。若聊天按鍵／點擊已開始但失敗，停止本次腳本，避免在殘留的聊天框繼續輸入動作。F10 共用既有 stop_event。

未啟用的既有腳本格式與行為維持相容。GUI 執行整合 AI 設定；CLI 與獨立規則播放器若未提供聊天服務，遇到已啟用設定必須明確報錯，不可靜默漏掉回覆。

## 驗證

測試設定存讀與驗證、字色分類、捲動去重、自己的訊息、上下文、嚴格回覆格式、停止／逾時／晚到結果、正確頻道與收件人、迴圈／子腳本接續、放鍵順序、GUI 設定存取與控制器接線。真實遊戲的頻道操作與文字輸入仍需在使用者配置位置後驗收。
