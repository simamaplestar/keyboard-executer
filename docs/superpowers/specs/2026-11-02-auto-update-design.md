# 自動更新 — 設計

日期：2026-11-02

2026-11-17 更新：依使用者要求，原始碼、發布與更新統一使用
`simamaplestar/keyboard-executer`。本專案使用 `simamaplestar` 的獨立登入設定。

## 為什麼

使用者把打包好的 `KeyboardExecutor.exe`（Windows onefile，約 134MB）手動傳檔給約 10 位朋友使用。每次出新版都要再傳一次，朋友也常停在舊版。目標：使用者發布一次，朋友的程式自己發現、下載、換上新版。

## 目標

- 朋友的程式啟動時自動檢查新版，有新版在背景下載。
- 下載完成跳出提示（新版號＋更新說明），朋友按「更新」→ 程式關閉 → 換上新 EXE → 自動重新開啟。
- 使用者（作者）一個指令發布：改版本號、打包、上傳、附更新說明。
- 朋友的資料（`~/.keyboard-executor/` 下的腳本、設定、模板、AI 金鑰）更新後完整保留。

## 非目標

- 不做差分／增量更新（每次下載整個 EXE）。
- 不做自動發布：平常改完只打包到 `packaging/dist/<名稱>/` 給作者自己測；**只有作者明說「發布」才發布**（使用者決定）。
- 不做 macOS 更新（朋友都用 Windows；macOS 建置照舊）。
- 不做強制更新、不做版本降級。

## 反目標（做到了也算失敗）

- 腳本、AI 示範試跑、規則監看、聊天自動回覆正在執行時跳出更新提示或自行重啟——會中斷遊戲操作。
- 下載中斷或檔案損壞後，朋友的程式打不開。
- 把發布者的 GitHub 憑證包進 EXE。
- 更新後朋友的腳本／設定不見。

## 使用者已決定的事

- 發布位置：原始碼與 EXE 更新統一放在公開倉庫 `simamaplestar/keyboard-executer`。
- 朋友端流程：啟動檢查 → 背景下載 → 下載完提示「新版 X 已下載，要現在重新啟動更新嗎？」＋更新說明 → 按更新才關閉、替換、重開。
- 正在執行腳本／試跑時不提示，停下後再提醒。
- 作者端：發布指令一次完成改版本號＋打包＋上傳＋更新說明；只在作者說「發布」時才跑。
- 首次發布前作者需在 Windows 上登入 GitHub 一次。
- 公開倉庫定案為 **`simamaplestar/keyboard-executer`**，更新與發布共用同一個 `REPO` 設定。發布指令在倉庫不存在時用 `gh` 建立（公開）。
- 不做發布簽章（Claude 建議、使用者未反對，交設計確認時再確認一次）：防偽靠作者 GitHub 帳號開兩步驟驗證；SHA-256 只防下載損壞。

## 限制與現況

- 版本單一來源：`src/keyboard_executor/__init__.py` 的 `__version__`（目前 `0.5.0`），`pyproject.toml` 同步；`.spec` 已從 `__version__` 讀版本。
- Windows onefile EXE：執行中的 EXE 不能被覆寫，但可以被改名。
- 朋友的程式可能放在任何資料夾（桌面、下載），名稱也可能被改過。
- 專案已有用標準函式庫 `urllib` 打 HTTP 的模組（`core/discord_notify.py`），不要為了更新新增大型相依。
- 從程式內下載的檔案不帶「網路下載」標記，Windows SmartScreen 不會再擋一次；但防毒可能延遲掃描新檔。

## 我（Claude）替使用者做的決定

- 用 GitHub Releases，每版一個 tag `v<版本>`，附件為 `KeyboardExecutor.exe`，Release 內文即更新說明。
- 版本比對用語意化版本（`0.6.0 > 0.5.10`），只在遠端版本**大於**目前版本時才更新。
- 完整性：發布時一併上傳 `KeyboardExecutor.exe.sha256`；朋友端下載完驗證大小與 SHA-256，不符就丟棄、下次再試。
- 替換方式：下載到 EXE 同資料夾的暫存檔 → 驗證 → 使用者按更新後，程式把自己改名為 `*.old`、把新檔改成原檔名、啟動新檔、自己結束；新版啟動時刪掉 `*.old`。任一步失敗就改回原名，舊版照常能開。
- EXE 所在資料夾不能寫入（例如放在 Program Files）時：不嘗試提權，改成提示「請到 <下載頁網址> 手動下載」。
- 檢查時機：啟動後延遲幾秒檢查一次，之後每 6 小時檢查一次（朋友可能長時間掛機）。
- 設定頁加「自動檢查更新」開關（預設開）與「立即檢查更新」按鈕、顯示目前版本。
- 網路失敗、GitHub 限流（未登入 API 每小時 60 次）時安靜略過，只寫 log，不打擾朋友。
- 從原始碼執行（非打包）時不檢查更新。
- 發布指令：`packaging/release.ps1 <版本> "<更新說明>"`，用 `gh` CLI 上傳；版本號必須大於目前版本，否則拒絕。發布前跑完整測試，失敗就不發布。
- 發布指令**不執行原始碼的 git 提交或推送**（不要求工作目錄乾淨），只改 `__init__.py`／`pyproject.toml` 的版本號、打包、上傳；Release tag 與原始碼位於同一倉庫。
- 多開：同一台電腦可能同時開好幾個程式。下載用鎖檔確保只有一個程式在下載；其他程式看到已下載好的同版本檔就直接用。按「更新」只替換 EXE 檔案（執行中的 EXE 可改名），不關閉其他程式；它們下次開啟才是新版。`*.old` 刪不掉（仍被其他程式占用）就留到下次啟動再刪。

## 留給實作者決定

- 「程式正在忙」的判斷方式：彙整主視窗既有的執行中狀態（腳本執行、AI 示範試跑、規則監看、聊天自動回覆）。
- 提示對話框外觀、「稍後」後多久再提醒。
- 重新啟動新 EXE 的細節（要保留原本的 `--dir` 參數）。
