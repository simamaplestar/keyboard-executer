## 腳本與錄製

### 腳本格式範例

```json
{
  "name": "每日簽到",
  "target_window": { "title_pattern": ".*遊戲名稱.*" },
  "settings": { "speed": 1.0, "repeat": 1, "humanize_jitter_pct": 10 },
  "actions": [
    { "type": "mouse_click", "x": 200, "y": 200 },
    { "type": "text_input", "text": "hello" },
    { "type": "loop", "count": 3, "actions": [
      { "type": "key_press", "key": "enter" },
      { "type": "delay", "ms": [200, 500] }
    ]},
    { "type": "wait_text", "region": null, "pattern": "完成",
      "mode": "contains", "timeout_ms": 5000, "on_timeout": "abort" }
  ]
}
```

座標一律為「目標視窗左上角為原點」的相對座標，視窗移動後腳本仍可用。

### 按鍵名稱

`key_press` / `key_combo` 的 `key` 用小寫 canonical 名稱，錄製與手動編輯都會存成同一組：

| 類別 | 名稱 |
|---|---|
| 修飾鍵 | `ctrl`（`control`）、`shift`、`alt`（`option`）、`cmd`（`win` / `super`） |
| 一般 | `enter`（`return`）、`esc`（`escape`）、`tab`、`space`、`backspace`、`delete`、`insert` |
| 導覽 | `home`、`end`、`pageup`、`pagedown`、`up`、`down`、`left`、`right` |
| 切換／系統 | `capslock`、`numlock`、`scrolllock`、`printscreen`、`pause`、`menu` |
| 功能鍵 | `f1`–`f20` |
| 數字鍵盤 | `num0`–`num9`、`num+`、`num-`、`num*`、`num/`、`num.` |
| 字元 | 單一可列印字元（`a`、`1`、`,`…） |

部分系統鍵僅適用 Windows；Mac 的按鍵與輸入模式限制見 [平台支援](../README.md#平台支援)。

**數字鍵盤是獨立的鍵**：`num7` 與主鍵盤的 `7` 是兩顆不同的實體鍵，遊戲裡可分別綁定，
錄製時會如實區分（靠虛擬鍵碼判定，NumLock 開著也不會混淆）。NumLock 關閉時
numpad 7 由作業系統送出的本來就是 Home，因此會錄成 `home`——這與實體行為一致。

### 錄製

錄製中會有一個置頂浮動窗即時顯示剛錄到的按鍵。錄製時人在遊戲視窗裡、錄製面板被蓋住，
靠它才知道按下去的鍵有沒有真的進腳本——**按了卻沒出現在浮動窗，就是沒錄到**。
浮動窗刻意不接受焦點，不會把焦點從遊戲搶走。

### 巢狀迴圈

在迴圈內新增動作時選「迴圈」，可設定內層次數並逐一加入動作。編輯內層迴圈會開啟動作清單，可繼續新增／編輯、調整順序；不需手寫 JSON。

## Windows 鍵盤輸入模式

| 模式 | 運作方式 |
| --- | --- |
| 一般模式 | 透過 SendInput 模擬按鍵。 |
| 遊戲模式 | 透過 DirectInput scan code 輸入。 |
| 前景訊息相容模式 | 對目前前景目標視窗傳送 WM_KEYDOWN／WM_KEYUP。 |
| 掃描碼脈衝模式 | 將長按拆成約 18ms 按下與 12ms 放開，反覆觸發按鍵。 |

Windows 提供四種每腳本鍵盤輸入模式。若一般模式與遊戲模式都收不到特定方向鍵，可先選「前景訊息相容模式」；它只會對目前位於前景、且與腳本目標 HWND 相符的視窗送出訊息，不支援背景輸入。目標程式若不處理視窗鍵盤訊息，可改試「掃描碼脈衝模式」，把長按切成反覆掃描碼按下/放開。兩種相容模式仍只使用標準 Windows 輸入 API，若目標程式過濾注入輸入，仍可能無效。

## 圖像模板與監看

模板是圖像規則與圖像動作**實際會去比對的那張圖**，兩處都看得到它：

- **模板管理**：清單每項帶縮圖，選取後右側顯示大圖與像素尺寸
- **規則編輯器**：條件選「圖像」時，模板名稱欄位下方即時顯示該張圖

名稱不存在時，預覽會顯示「找不到模板」與該名稱，可先修正再開始監看。

開始監看後, 圖像規則會在日誌記錄模板名稱、相似度、門檻、搜尋區域及視窗尺寸。
首次比對、命中狀態改變或每隔 30 秒才記錄一次; 找不到目標視窗也會提示。
規則真正觸發時另有「命中, 觸發 notify」紀錄, 可區分圖片沒有辨識到與通知傳送失敗。
模板採原始像素大小比對, 遊戲介面縮放或模板來自縮放過的相片時, 需重新擷取固定提示文字。

## 匯出與匯入

標題列的「匯出／匯入」把勾選的腳本與規則存成**單一 JSON 檔**，傳一個檔給別人就能用。

會自動一併打包的相依項目（漏掉任一項，對方匯入後就是壞的）：

- 圖像動作（`wait_image` / `if_image` / `click_image`）與圖像規則用到的**模板圖片**（base64 內嵌）
- `run_script` 動作、以及規則的 `run_script` 觸發所呼叫的**其他腳本**（遞迴解析）
- 巢狀動作（`loop` 的 `actions`、`if_*` 的 `then` / `else`）裡的引用同樣算數

沒被任何項目引用的模板不會進包，所以檔案通常很小。按下匯出前，對話框就會顯示實際
會帶走什麼（含自動補上的相依），引用了已刪除的腳本或模板也會當場警告。

兩件刻意的行為：

- **`settings.json` 永遠不會被匯出**。裡面有 Discord webhook 與 AI 金鑰，匯出等於把憑證一起交出去。
- **匯入遇到同名一律先問**。選「否」則保留你現有的版本，只匯入其餘項目，不會靜默覆蓋。

## AI 助手設定

設定頁可選兩種認證方式：

- **API 金鑰**：支援 Anthropic/OpenAI/OpenRouter；API 用量與訂閱分開計費。OpenRouter 選取平台後填入 API Key 與完整 model ID（自行輸入），不需另外設定網址。
- **訂閱登入**：ChatGPT 透過 OpenAI Codex `app-server` 的官方帳號介面；Claude
  透過本機 Claude Code 的 Pro/Max 登入，或 `claude setup-token`。設定頁會先選
  ChatGPT／Claude 平台，再從各平台的模型下拉選單選擇，也可自行填入 model 名稱。
  Codex 的「更新模型」會向本機 Codex 讀取帳號可用清單；查詢失敗保留現有選項。

訂閱模式需要先在使用者電腦安裝相應的官方工具：

```powershell
# ChatGPT / Codex（安裝後可直接在設定頁登入）
npm install -g @openai/codex

# Claude Code（Windows 官方安裝方式）
winget install Anthropic.ClaudeCode
```

Windows PATH 找不到工具時，App 也會自動偵測 WSL 登入 shell 裡已安裝的
`codex`／`claude`，不必為打包版重複安裝一份。

App 不讀瀏覽器 cookie 或帳號密碼。Codex OAuth token 由 Codex 自己管理；Claude
`setup-token` 存於 Windows Credential Manager 或 macOS 鑰匙圈，不寫入 `settings.json`。訂閱達限時會
顯示提示，不會未經同意自動切換到可能計費的 API key。若官方工具不在 `PATH`，設定頁
會顯示安裝提示。

macOS 可使用相同的 `npm install -g @openai/codex` 安裝 Codex；Claude Code 依官方
macOS 安裝方式安裝後登入。從 Finder 開啟 App 時，程式會用登入 shell 查找終端機裡
安裝的工具；鑰匙圈要求存取 Claude token 時需允許。

### 示範錄製

在 AI 助手面板按「示範錄製」，框選小地圖並手動示範一圈操作。程式會記錄按鍵按住時間，每 500ms 擷取一張圖片，再由 AI 產生操作腳本與回起點腳本。

程式會在目標視窗試跑、與示範比對並修正，預設最多三輪、每次最多 30 張截圖，可在設定頁調整。腳本庫保留實際試跑過的版本，總結卡片可退回先前版本。

## 聊天自動回覆

1. 在設定頁選擇 AI 供應商、登入或填入 API Key，並使用**支援圖片的模型**。ChatGPT 訂閱可按「選擇模型 ▼」展開帳號可用模型清單，首次會在背景讀取；也可保留「自動選擇」。
2. 編輯腳本，指定遊戲視窗，按「AI 自動回覆」。填入自己的角色名稱，框選聊天內容及底部輸入列，包含左下角的頻道／密語對象按鈕與旁邊白色輸入框，再分別勾選「地圖聊天」與「密語」。兩者都關閉時暫停 AI 監看與回覆。
3. 依需要編輯回覆提示詞、檢查間隔、AI 等待上限與回覆長度上限。程式會自動判斷回覆對象與頻道，輸入回覆、確認送出並退出聊天輸入，再接續腳本的下一個動作。
4. 啟用後按「套用至腳本」，再儲存腳本。從 GUI 執行時使用當前 AI 設定。

### 什麼訊息會觸發回覆

收到密語的格式為 `姓名[CH.頻道]>> 內容`（也支援 `CH-頻道`），回覆時只使用姓名；送出紀錄不觸發 AI。第一次讀取只建立上下文，不回覆畫面上原有的舊訊息。之後只讓新綠字／白字觸發 AI；自己的訊息、其他顏色和已處理內容不會重複觸發。密語原則上回覆，地圖聊天由 AI 判斷是否與自己有關。

### 對話保存與玩家區分

對話依「自己的角色名稱 + 對方完整角色名稱」分開保存, 頻道編號不是玩家身分的一部分。每位玩家最多保留最新 50 筆, 對方的訊息與自己回給該玩家的訊息都占一筆; 超過時移除該玩家最舊的紀錄, 不影響其他玩家。公告、不確定姓名和無法歸屬對象的公開發言不占玩家的 50 筆額度。紀錄自動存到資料目錄下的 `.chat-history/`, 停止腳本或重開程式後會讀回; 開始監看時不會把畫面上的舊訊息重複存入或補發回覆。尚未成功送出的 AI 草稿不會記成已回覆。

AI 每次只處理一位玩家的對話, 自己的回覆附有對應收件人。送給 AI 的文字與聊天圖片都限於該玩家; 回覆地圖頻道時只提供公開對話, 不引用密語。多人同時傳訊息會依序在背景處理, 另一位玩家的新訊息不會讓已準備好的回覆反覆重算。同一玩家的同頻道新訊息則會合併重新判斷。名稱只差一字的玩家仍分開, 不因長句相似就視為同一人。

### 頻道設定與提示詞

關閉某頻道後，該頻道只保留在上下文，不會觸發 AI 或送出回覆。預設提示詞採朋友聊天的繁體中文短句，可以打屁、接梗與輕鬆嘴砲，認真問題直接回答；要求標點使用 ASCII 半形，也可用空格斷句。被問到 AI／腳本時簡短帶過，不解釋工具或系統。提示詞可自行編輯，前兩版原始預設會在載入時更新，自訂內容會保留。

### 頻道確認與送出流程

頻道確認以灰色對象按鈕與白色輸入框的版面定位，再辨識按鈕或選單文字；展開的選單由程式另外擷取，不必框進聊天區域。密語與地圖回覆確認送出後，都會選回「對所有人」，確認空白輸入框後退出輸入再接續腳本。地圖回覆前已確認是公開頻道時不再展開選單。若按鈕、選單項目或切換結果無法確認，會停止腳本並顯示原因，避免地圖訊息誤送到密語或其他頻道。這些確認只在回覆期間執行，不增加平常迴圈的辨識工作。舊版儲存的回覆操作與自動頻道開關不再控制送出流程；開啟設定並套用後會清除舊操作。

固定的密語視窗標題、頻道按鈕和選單標籤會接受 OCR 產生的繁簡字形差異, 例如「請／请」與「對／对」; 仍須符合完整標籤、信心值及版面確認。玩家姓名與聊天文字保留原始辨識結果。

打字後會等待文字出現；送出 Enter 後，確認輸入框連續呈現空白才記錄已回覆。若相同文字仍留在框內，最多補按兩次 Enter，每次都先等待並檢查，成功後不再多按。確認失敗會保留文字並停止，不切頻道或按 Esc；若執行回覆前已有草稿，也不會直接送出或蓋掉。輸入框以小範圍像素檢查，不額外執行 OCR。長中文句子填滿輸入列時, 會同時檢查白底邊緣與字形, 避免只因文字密集就誤判為遮擋; 游標或色塊遮住欄位時仍不直接送出。

AI 回覆操作之間至少間隔 300ms, 包含選取姓名、輸入文字、Enter 與點擊; 畫面確認已花費的時間也計入間隔。頻道點擊按住 100ms, 放開後等待 300ms 才辨識。選單與切換結果若第一次讀不清楚, 最多讀取三次, 不連點重開選單。這些等待只用於 AI 回覆, 不改變原腳本一般動作的速度。

選回「對所有人」後, 會將游標移到聊天框選區外的視窗內位置, 預留游標圖案的空間, 等待 300ms 重繪後才確認頻道與輸入框, 避免游標停在聊天文字上遮擋後續辨識。

密語輸入姓名前也會確認「請輸入密語對象」視窗, 姓名後的 Enter 必須確實關閉該視窗才輸入正文。視窗和原姓名仍在時, 最多補按兩次 Enter; 若視窗被遮住、名稱改變或出現其他對話框, 則保留現場並停止。這個視窗由程式另外擷取, 不必擴大原本的聊天框選。

框選包含底部「對所有人」等固定介面文字也可使用；它們與重複公告不會遮蔽新訊息的判斷。首次讀取完成時，執行紀錄會顯示「聊天監看已就緒，等待新密語／地圖對話」。新訊息辨識完成就立即顯示「偵測到」, 即使前一個 AI 請求仍在進行; 真正開始 AI 處理與送出結果分別記錄。

### 背景辨識與執行時機

聊天由獨立背景工作排程，長按、拖曳或延遲期間也會依間隔擷取、辨識並處理新訊息，不必等下一個動作。OCR 使用獨立程序，首次載入模型與定時檢查不會要求原腳本等待。發現新訊息後，先在背景產生 AI 回覆，原腳本繼續執行；等待 AI 時仍持續監看，後續新訊息會合併重新判斷，不同時重複發出多個 AI 請求。有回覆待送時，等目前動作結束，再於**動作之間**暫停、確認最新聊天並送出；原播放器保留目前的迴圈次數、子腳本與下一步位置，回覆後不會從頭執行。若確認時讀到新訊息，會重新納入上下文，在背景請 AI 再判斷，原腳本繼續跑。

檢查間隔從每次掃描開始計算。同時最多進行一次聊天掃描；若單次 OCR 超過設定間隔，完成後才開始下一次，設定 1 秒不代表辨識或 AI 回覆一定能在 1 秒內完成。畫面像素完全相同且已有文字結果時沿用上次辨識，送出前重查也適用；畫面變動或上次未讀到文字則重新 OCR。AI 產生內容、判斷不需回覆或請求失敗都不會要求腳本等待 OCR；有待送回覆時的最後確認與輸入才會暫停，以免確認後又隔一個長按才送出舊回覆。

### OCR 模型與效能

所有 OCR 入口（聊天、圖片順序輸入、文字等待／點擊／條件及規則）均使用 **PP-OCRv6 tiny + ONNX Runtime**。聊天與圖片服務共用可取消的背景 OCR 子程序，載入一次後重用；以單行批次減少長短句混合時的填補運算。發布 EXE 包含離線模型；從原始碼執行前先依 [打包說明](../packaging/README.md) 準備模型。模型缺失或損壞會明確報錯，不會下載或退回舊引擎。設定頁固定顯示新版自動辨識；舊 OCR 語言欄位仍保存在設定檔，但不再切換模型。聊天掃描明顯超過間隔時，日誌會列出擷取、辨識及引擎等待、掃描鎖等待的秒數。首次載入模型仍需額外時間。

聊天、按鈕、選單與密語視窗標題分別保留最近的辨識結果, 每次仍擷取並比對當前像素。ChatGPT 訂閱的自動回覆會先確認指定模型支援 `low` 推理量才使用; 模型留空、能力未知或不支援時沿用原設定, 不更換模型。這項設定僅用於聊天自動回覆。日誌分別記錄 AI 產生、等待目前動作完成、畫面確認與輸入的耗時, 以及送出失敗原因。

### 主腳本與子腳本

聊天設定以本次執行的**主腳本**為準；同視窗的子腳本沿用主腳本設定。若透過 `run_script` 呼叫子腳本，請在主腳本啟用此功能；子腳本切到其他視窗時不會把該視窗當成聊天來源。

### 重試、停止與通知

AI 回覆若未通過 JSON 或欄位驗證, 會保留這批訊息, 在背景請 AI 修正一次, 避免第一次格式錯誤就漏掉密語。兩次請求共用原設定的等待上限, 原腳本繼續執行, 通過完整驗證才允許送出; 不會將無效正文直接當成聊天內容。有效的「不需回覆」結果不重試, 連線錯誤也不使用格式重試。

AI 失敗或逾時會記錄原因，腳本繼續執行；若已開始輸入回覆卻發生操作錯誤，則停止腳本，避免把後續按鍵打進聊天框。F10 仍可停止，不必等 OCR 運算結束；停止或腳本結束後，晚到的辨識與 AI 回覆會丟棄，OCR 子程序在背景回收。CLI 與獨立規則執行器目前不提供聊天服務，會明確拒絕執行已啟用此設定的腳本。

若 AI 回覆流程導致腳本停止, 會使用設定頁既有的 Discord webhook 傳送腳本名稱與停止原因, 包含初始化、密語對象確認、送出及切回公開頻道失敗; 每次執行最多通知一次。通知在背景傳送, 傳送失敗不會取代原本的錯誤。手動停止、AI 判斷不需回覆, 或 AI 請求失敗但腳本仍繼續的情況不發停止通知。

### 使用限制

畫面辨識無法還原檢查間隔內已捲出畫面的聊天；完全相同的新舊畫面也可能無法區分。請保持聊天框可見，並依聊天量調整檢查間隔。AI 回覆內容與遊戲內文字輸入、頻道切換，仍需以實際設定驗收。

## 圖片順序輸入

在腳本編輯器按「圖片順序輸入」，勾選啟用，**只框選一次完整面板**（包含提示、輪播圖片、輸入框及確認按鈕），儲存腳本。不用再填提示文字或分別取點。

### 提示偵測與模型使用

新版單框與舊版手動設定的提示比對都接受繁體、簡體及混寫；僅提示比較使用 OpenCC 正規化，不更改原始 OCR 文字、玩家姓名、一般文字或正則比對。平常每秒在本機執行 OCR；提示符合內建白名單且命中文字信心值至少 0.8，才把完整框選圖送給設定頁的圖片 AI 模型。支援「請按照號碼順序輸入文字」、「請依照編號順序輸入文字」、「請按順序輸入文字」及繁簡、空白、標點變體。空白、低信心或未支援措辭不會偷偷轉交 AI。新模式啟動時不做遠端 AI 預檢，等待提示期間沒有此功能的 AI 用量。

### 暫停與恢復腳本

**只有圖片順序輸入採中途暫停**：OCR 確認提示後，長按／等待以至多 20ms 的合作式檢查片段停下，先放開按鍵，再開始 AI 辨識；不再等整個長按或等待結束。完成後接續剩餘時間，已送出的字元／點擊不重播。短點按中斷後不再按一次；拖曳若已開始，會放開滑鼠、處理圖片後停止，請人工確認畫面。作業系統或 OCR 的單次不可取消呼叫仍須等返回，不是硬即時中斷。聊天本身仍維持原本動作之間處理。

監看真正開始時會印出一次 INFO「監看已啟動」，包含框選區域及 Discord 是否已設定；沒有提示時不每秒洗版。只有儲存設定、尚未執行腳本，不會開始監看。

### 定位與辨識

輸入框與確認按鈕由**本機影像處理**定位（白色輸入框、綠色按鈕，連續兩次定位 IoU 穩定才允許點擊）；輪播編號優先由**本機 OCR** 讀小圖四角（編號可能出現在任一角落）；本地讀不出時，同一張圖（感知雜湊分組）會以 AI 編號後援累積投票，2 票且嚴格多數、且不與其他圖的編號衝突才採用，衝突永不猜測。AI 只需要辨識放大後輪播小圖的**單一 ASCII 英數字**。同一編號的字元需累積 2 票且嚴格多數才鎖定（單次誤讀不再立刻失敗；平手永不鎖定，逾時停止）。收齊三個不同編號 1、2、3 後，使用 Ctrl+A 選取原文字、依序填入，**只點一次確認**。位置無法確認時不猜、不亂點。字元辨識的回應解析容忍單層 markdown 圍欄與 JSON 後多餘文字，但欄位 schema 嚴格驗證；部分模型會因政策拒絕辨識扭曲字元，此時全部視為不確定，不會亂猜。

### Discord 通知

**OCR 首次偵測到提示時，也會同時啟動 Discord 文字通知**，沿用設定頁 Webhook，每回合一次、不附截圖。通知與 AI 處理並行，不等待通知送達；5 秒傳輸逾時、不重試。未設定 Webhook 或傳送失敗會在本機提示，不影響辨識與原本截止時間。

### 舊腳本相容

舊腳本仍保留「舊版手動設定」與原本啟動 AI 預檢；按「改用單一框選」並成功框選後才轉換，取消不會改動原設定。

### 時間限制與停止條件

**從首次命中提示的畫面擷取時間起，共用 18／20／30 秒期限**：18 秒前收齊編號 1～3 並通過安全定位、準備輸入；20 秒前輸入答案並按一次確認；確認後驗證提示消失，整輪仍不能超過 30 秒。OCR、等待放鍵及所有 AI 批次都計入，不因模型回應或切換階段重新起算。AI 不再單獨固定 10 秒就中止，而是使用回合剩餘預算；已開始輸入時，定位安全觀察最多持續至 20 秒。超時、失焦、視窗移動或辨識失敗就停止，不補送、不自動重試。F10 仍有效，晚到結果不能恢復輸入。這是截止規則，不保證 API 模型或不可中斷的系統呼叫一定能在 20 秒內完成；定位新鮮度與其他安全檢查不放寬。

圖片流程優先於聊天；新模式確認後只用本機 OCR，連續兩次相隔至少一秒的有效畫面顯示提示已消失，才接續原腳本。沒有可讀文字或低信心 OCR 不算成功，寧可逾時停止。若提示出現時聊天已輸入到一半，解完後仍會停止並保留草稿，避免把遊戲按鍵打進聊天框；請人工確認焦點再執行。不同視窗的子腳本不會收到圖片答案。此功能目前只供 GUI 主腳本執行，CLI／獨立規則會明確拒絕已啟用的設定。

### 辨識限制與資料處理

新版 OCR 在部分完整面板小字上仍可能把「請」讀成「讀」。命中提示主體但首字錯讀或漏字時，只算不確定，不觸發 AI，也不能當作提示已消失；這項保護不會修好漏觸發。離線圖片結果與發布驗證見 [全入口 OCR 遷移報告](unified-ocr-migration-report.md)。

僅將框選圖片送給目前 AI 供應商；截圖與模型回應預設不持久保存，訂閱工具使用的暫存圖片會在請求結束後清除。腳本匯出包含框選／取點設定，不含金鑰。

### 視窗狀態與實機驗收

偵測不要求目標視窗位於前景：視窗在背景但畫面可見時仍能觸發並發送 Discord 通知，輸入答案前會自動把目標視窗切回前景，切不回來就停止、不送出。但截圖取的是螢幕像素，遊戲被其他視窗遮擋或最小化時仍讀不到提示；確認後的「提示消失」判定也只信任前景畫面，避免把遮擋誤判為消失。另開看圖視窗測試時不可蓋住遊戲畫面；可另建只含短等待循環的測試腳本，以看圖程式為目標並重新框選面板。固定編號 1 圖片只能測提示偵測，無法收齊 1～3 或驗證真實輸入。啟用此功能時，聊天不會搶回已失去的焦點；失焦時停止。每秒取樣可能漏掉過快輪播，OCR、網路及模型速度也會影響成功率；30 秒是停止上限，不是辨識必定成功的承諾，也不是作業系統硬即時保證。提示消失只表示本機觀察到視窗關閉，**不代表已驗證伺服器接受答案**。實機驗收項目見 [圖片順序輸入驗收表](sequence-input-manual-checklist.md)。

## 開發參考

### 專案結構

三層設計，平台差異全部隔離在 `platforms/` 層：

```
src/keyboard_executor/
├── core/        # 純邏輯：models（腳本/規則驗證）、player（回放狀態機）、
│                #   recorder（事件→動作）、vision（模板比對/文字搜尋）、rule_engine
├── platforms/   # 平台抽象（唯一允許 sys.platform 判斷）：base 五介面 +
│                #   common（pynput/pywinctl/mss）+ win32 + darwin
├── storage/     # 腳本 / 規則 / 模板 JSON + PNG 檔案存取
├── app/         # PySide6 GUI（唯一含 Qt 的層）
├── cli.py       # CLI 進入點
└── gui.py       # GUI 進入點
```

核心邏輯以 fake 平台實作注入單元測試；實際 OCR、螢幕擷取、打包及真實遊戲操作需另做離線圖像或實機驗收，不能由單元測試推定準確率。

### 主要套件

| 能力 | 套件 |
|------|------|
| GUI | PySide6 |
| 輸入模擬 | pynput；Windows 遊戲補充 pydirectinput；前景視窗相容模式使用 Win32 PostMessage |
| 全域監聽 | pynput |
| 視窗控制 | pywinctl |
| 截圖 | mss |
| OCR | 全入口共用 PP-OCRv6 tiny + ONNX Runtime（CPU、離線模型） |
| 模板比對 | opencv-python + numpy |
| 打包 | PyInstaller |
| 測試 | pytest |

測試指令、打包與實機驗收入口見 [README](../README.md#開發與文件)。
